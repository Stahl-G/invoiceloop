## S1 否定了什么(关账数字,开发集)

核心假设:「自动掉一部分槽 + AI 预读建议」能把人时降到可普查十字段的程度。

关账(`closeout_run-0002.json`):

- 槽 200;人工队列 **92**;`auto_accept` 81;`auto_absent` 27
- **20/20 张都被打开**(零触达 0)。字段自动率约 54%(108/200),合取十字段
  后张数照旧全碰 —— 与 `scripts/doc_touch_economics.py` 的算术同一件事
- 94 条裁决;计时 90 段,中位 **52.0 秒/槽**(accept 25 · correct 58 ·
  confirm_absent 43.5 · reject 53.5)
- 对照臂:hitl-sealed `run-0002` 纯人时中位 **28 秒/槽**(120 槽)。S1 是
  「AI 预读 + 人确认」组合臂,不得解释成系统单独变慢;但组合臂也**没有**
  把人时打下来
- 建议:`agree` 32 / `split` 36 / `blind` 16 / `agree_rejected` 10;
  采纳率 20/32 = 0.625(分母只含 agree)
- 决策以 `correct` 为主(关账 47/94),不是确认

人主要在处理口径,不是核对印在纸上的数。按字段的相邻间隔(最新 tip、>1h
剔除,开发集补充观察,不是关账口径):卖方名中位 156s、VAT 号 120s、买方名
104s、到期日 59s;金额槽 24–32s。贵的是 agency/广告主/NET 30,不是 Gross。

阶段化增补件预计每段 30–40 分钟。S1 相邻间隔加总约 3 小时。预估偏了大约
五倍,照登。

S1 无晋升。HAR-0021 保持冻结。这与「不以人审为 schema 金标准」一致,也与
「S1 人裁不带进 S2 路由」一致。

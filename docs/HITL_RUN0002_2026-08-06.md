First real human test. Subject = the project author (warm, not an uninformed
subject — the uninformed retest is still outstanding;
`docs/TESTING_FACILITATOR.md` is ready). Target: `runs/hitl-sealed` (the 12
documents drawn in SEALED-1 with `random.Random("hitl-sealed-2026-08-05")`;
evaluation already recorded as-is, demoted to a regression set; human
adjudications pollute no published numbers). Policy: HAR-0002 (removes forced
human review for conflict-free TIER1). Queue: 75 slots awaiting review / 120
total slots.

## Totals

- **123 adjudications covering 120/120 slots** (3 supersessions), completed
  over two evenings;
- Decision mix: **accept 67 · correct 24 · confirm_absent 26 ·
  not_applicable 4 · reject 2**;
- Duration (medians, server timestamps; overnight intervals contaminate
  means, so only medians are reported): **all 28s/slot**; accept **20s** ·
  correct **66s** · confirm_absent 44s · reject 95s · not_applicable 90s.

## The one-click fast path is the main channel

74/123 (60%) used the fast path's preset reasons. The three one-click buttons
"✓ original value correct / adopt DWS value / confirm absent" compressed
accept-type decisions to a 20s median — this round's most direct labor
evidence: **the bulk of review cost is not "confirming the right ones", it is
"re-entering the wrong ones"** (correct 66s).

## The human increment: 24 corrects

Values DWS did not provide or got wrong: the human re-entered 24 from the
pages — dates (6), buyer/seller names (6), amounts (6), invoice numbers (1),
tax ids (1), others (4). Without the human, these values would enter the
deliverable as missing/wrong. **The review queue's incremental value is no
longer narrative; it is 24 ledger entries.**

(Honest registration: one of the corrected values, `105528107477215711`
(f2caad44/seller_vat_id), has a suspicious shape, like an OCR smear copied
over — warm subjects also make mistakes, which is exactly why the QA
spot-check exists.)

## Two findings that go straight into the improvement loop

1. **absent_expected cohort (landed as an HAR-0003 candidate)**: seller_vat_id
   12 slots = 9 confirm_absent + 1 N/A + 1 correct + 1 reject — US invoices
   lacking VAT is a general pattern; repeatedly confirming absence has been
   taken over by the word-class path (QA 20% watches absence plausibility).
2. **Fed. I.D. → seller_vat_id wrong mapping** (8c2273ca): the page prints
   Fed. I.D. (EIN), DWS maps it into seller_vat_id, and machine checks come
   back all green — binding proves "the value is on the page", not "it belongs
   to this field". Per DocILE convention (this document's vendor_tax_id
   annotation is null), adjudicated **reject + WRONG_FIELD_MAPPING**. This is
   systematic over-extraction inside a scoring blind spot; a candidate
   monitoring direction.

## Feedback quality (honest registration)

Reason codes 8/123, confidence 3/123 — the optional fields are barely used,
and mine's qualifying events remain near zero. **The quality gate again
proves it is not decoration** (garbage does not enter mining), but the
improvement loop's automation level is limited by this; next round improves
via reason-code quick chips and fast-path default reason codes (presetting
ROUTING_FALSE_POSITIVE etc. when the human confirms a value), without setting
default values (the system does not fill in for the human).

## UI defects fixed during the subject's run (all with regression tests)

run-0002 had no full-page rendering, a two-column layout that did not fit, no
"original value correct" fast path, CLEAN placeholders swallowing the QA
enqueue reason, language switching dropping parameters into 404, no page
switcher for multi-page documents, adopt-suggestion broken on the
adjudication page, no search box, a wrong default state for the evidence
area, and an over-thick highlight box. **This is HITL's other half of the
output: 9 presentation defects that only real usage exposes.**

## Conclusions

- Queue composition is sound: claim-less/missing-value/gate-failed slots
  dominate, and the QA spot-check share is small and well-defined;
- The labor distribution supports "let machine-guaranteed slots go to the
  machine": accept 20s vs correct 66s; HAR-0002's direction (reducing
  confirmation-type human work) is supported by real timing data;
- Warm subject + 12 documents is the ceiling: uninformed subjects, larger
  batches, and precise reviewer-minutes timing belong to the next round
  (protocol in `docs/TESTING_FACILITATOR.md`).

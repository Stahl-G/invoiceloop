# R0 baseline, measured (2026-08-05, HAR-0001)

The v0.2 design §14 requires: before any "41%→30%" narrative, re-measure R0 first under the corrected
caliber (design prohibition #16: it is forbidden to call 41.1% the document review rate unless measured
to be so). This document is the measured result. **41% is not R0.**

Recompute (zero API, stored evidence):

```bash
INVOICELOOP_CORPUS=runs/heldout-workspace python3 -m invoiceloop run \
  --out <new-dir> --doc-ids <100 ids>   # or use runs/heldout-r3 directly
```

## Measured (runs/heldout-r3, 100-document held-out set × 10 fields = 1000 slots)

| Metric | Value | Caliber |
|---|---|---|
| mandatory field review load | **61.2%** (612/1000) | share of `requires_adjudication` slots (triage caliber) |
| document touch rate | **100%** (100/100) | share of documents with at least one slot needing review |
| decision_load_for_release | **82.3%** (823/1000) | slots requiring explicit human adjudication to release a whole document (requires ∪ TIER1), given per run by deliverable.summary |
| TIER1-only counterfactual triage load | 41.8% | only the 287 ground-truthed TIER1 slots (the caliber of the earlier three-way baseline tables) |

## The true identity of "41%"

The 41.8% in the three-way baseline tables is the **TIER1-only, ground-truthed-subset, counterfactual
auto-release** caliber — three narrowings stacked. Measured under the conservative policy over all slots
and all documents: 61.2% field review, 100% document touch, 82.3% release decision load. Outward
narratives use this table's numbers without exception; 41.8% is allowed to appear only in the context
of "counterfactual triage-signal quality", side by side with same-caliber baselines.

## Caliber split (architecture adjudication eight: operational and safety metrics may not share a denominator)

**Operational metrics (no ground truth, all 1000 slots)** — human workload:
mandatory field review load 61.2%, document touch 100%,
decision_load_for_release 82.3%, automatic release rate 0%, block rate 0%.
(All-pending is the result of this run having zero adjudications — the review queue is waiting
for a human; the system is not broken.)

**Safety metrics (ground-truthed subset, 574 scored slots / 287 TIER1 slots)** — error rates:
see docs/BASELINE_COMPARISON.md; the TIER1 counterfactual triage load 41.8% belongs to this class,
with "slots judgeable against ground truth" as the denominator, not operational workload.

The two classes have different denominators and answer different questions; any "41→30"-style narrative
must first state which class it uses. Reviewer minutes / actions per invoice requires real-human timing
and was not measured this cycle (testing discipline: do not fabricate what was not measured).

## What these numbers say

- Under the conservative policy **every document needs human hands** (touch 100%) — this is precisely
  the reason the improvement layer exists, not a number to be ashamed of: R0's job is to intercept
  everything suspicious for humans, over-blocking rather than under-blocking;
- Room for improvement genuinely exists: how many of the 612 review-needed slots are low-yield soft
  reviews is answered by R1's cohort statistics (improve mine);
- R0's HAR-0001 is **byte-for-byte equivalent** to the pre-2026-08-05 inline triage (heldout rerun with
  zero diff, pinned by tests/test_routing.py), so this table is simultaneously a measurement of the
  pre-existing system, not new behavior.
